# Проверка правил на казахской и смешанной речи, набор v4 (01.11.2026)

Два файла, фразы в стиле распознавания речи (строчные буквы, без знаков препинания):
- `dev.csv`: 25 мошеннических и 22 обычные фразы. На ошибках этого набора дорабатывались правила;
- `holdout.csv`: 28 мошеннических и 28 обычных фраз. Записан и сохранён отдельным коммитом **до** изменения правил,
  правила по нему не подгонялись. Измерен один раз до изменений и один раз после.

Предупреждение = средний или высокий риск.

| | dev до | dev после | holdout до | holdout после |
|---|---|---|---|---|
| Мошеннические фразы с предупреждением | 13 из 25 | 23 из 25 | 13 из 28 | **16 из 28** |
| Из них высокий риск | 5 из 25 | 5 из 25 | 4 из 28 | 5 из 28 |
| Ложные предупреждения | 3 из 22 | 0 из 22 | 2 из 28 | **0 из 28** |

Старые наборы после изменений не ухудшились: v1 30 из 30, v2 29 из 30, v3 34 из 34, ложных 0.

Выводы:
- на наборе, по которому правила не настраивались, результат намного ниже (16 из 28, 57 %), чем на рабочем (23 из 25).
  Это и есть честная оценка для казахской речи: правила в виде шаблонов плохо переносятся на новые формулировки,
  потому что в казахском много окончаний и порядок слов свободный;
- ложных тревог на обычных казахских фразах не стало (было 2 из 28);
- часть пропусков сделана так намеренно: одна фраза с одним приёмом («я из службы безопасности», «никому не говорите»)
  не даёт предупреждения ни на русском, ни на казахском. В реальном звонке риск складывается из нескольких фраз.

Ограничения:
- оба набора написаны одним автором, это не записи настоящих звонков. Нужен набор от других людей;
- 56 фраз в контрольном наборе — мало для точных процентов;
- holdout теперь использован. Для следующей проверки нужен новый набор, его тоже нельзя использовать для настройки.

Запуск: `python -m experiments.text_eval_v4.run_eval dev` или `... holdout` из корня репозитория.
