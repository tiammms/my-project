# Дорожная карта внедрения

> Прототип не внедрён ни в один банк. Ниже — как его можно было бы честно проверить и внедрить. Сроки ориентировочные.

| Этап | Цель | Ресурсы | Риски | Критерий завершения | Метрика перехода дальше |
|---|---|---|---|---|---|
| **1. Data & Baselines** (2–3 мес.) | Повторить эксперимент на исторических данных банка | 1 DS, 1 data engineer, доступ к обезличенным транзакциям и подтверждённым мошенничествам; правовое основание обработки | Метки неполные; утечки при построении признаков; нет телеметрии | Признаки построены time-respecting; baseline = **реальные правила банка**; отчёт по той же методике | PR-AUC гибрида выше правил с непересекающимися 95% CI; FPR ниже на ≥ 30% при равном recall |
| **2. Shadow mode** (3 мес.) | Оценивать живой трафик **без влияния на платежи** | Интеграция по API в режиме «только запись», мониторинг, 1 аналитик для разметки | Задержка влияет на поток; дрейф данных | ≥ 3 месяцев логов; разбор всех HIGH; latency SLO выполнен | p99 < 100 мс под реальной нагрузкой; метрики стабильны по месяцам; FPR по сегментам (новые клиенты, пожилые) не хуже правил |
| **3. Controlled pilot** (3 мес.) | Включить step-up для части клиентов (например 5%, A/B) | Команда антифрода, UX предупреждений, юрист, DPIA | Недовольство клиентов; социальная инженерия «уговаривает» пройти step-up | Предотвращённые потери и жалобы клиентов измерены против контрольной группы | Статистически значимое снижение потерь или нагрузки на аналитиков; жалобы не выше контроля |
| **4. Gradual rollout** (6 мес.) | Расширение на всех клиентов, затем включение HIGH → рекомендация удержания | Security review, пентест, нагрузочное тестирование, согласование с регулятором | Регуляторные требования; отказоустойчивость | Аудит пройден; runbook и откат готовы | Целевые SLO выполнены 2 месяца подряд |
| **5. Continuous monitoring** (постоянно) | Следить за дрейфом и новыми схемами | MLOps, ежемесячный отчёт, канал обратной связи аналитиков | Деградация модели; адаптация мошенников | Дашборд дрейфа (PSI признаков), еженедельный пересчёт метрик по свежим меткам | Алерт и переобучение при падении PR-AUC > 10% или PSI > 0.2 |

## Эксперименты для известных ограничений

| Ограничение | Следующий эксперимент |
|---|---|
| Синтетические данные | Этап 1 на реальных данных; дополнительно — публичный датасет с метками мошенничества для транзакционной модели |
| Счета младше 30 дней: 9.0% ложных тревог против 2.1% у правил (после исправления двух ошибок измерения; опция отдельного порога — 1.6% ценой части recall) | Проверить компромисс на реальных данных; дать банку выбрать порог по своим стоимостям ошибок |
| Адаптивный противник (измерено: −2.5…−12.4 п.п. за один скрытый сигнал; обучение на примерах обхода не обобщается на новые приёмы) | Новые независимые сигналы (например, проверка получателя через другие банки), регулярное переобучение |
| Нагрузка (измерено: ~90 запросов/с на процесс, ~165 на двух; задержка 44 мс у 2 процессов устранена) | Нагрузка за обратным прокси на отдельном сервере; перевод SQLite → PostgreSQL |
| Docker не проверен | Сборка и прогон `scripts/e2e_check.mjs` внутри контейнера в CI |
| LLM-отчёты | Подключить локальную LLM через адаптер, ограничив её фактами шаблонного отчёта; измерить время аналитика до и после |
