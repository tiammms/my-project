# Технические решения и отступления от предпочтительного стека

В среде разработки был заблокирован доступ к PyPI и npm. Поэтому использовались только уже установленные библиотеки. Каждое отступление ниже — осознанная замена, чтобы всё можно было **реально запустить и проверить**.

| Предпочтительно | Использовано | Почему / последствия |
|---|---|---|
| FastAPI | **Starlette 1.6 + Pydantic v2** и свой слой маршрутов (`backend/app/api/framework.py`, ~150 строк) | Starlette — это основа FastAPI. Своя прослойка делает валидацию тела и query, отдаёт очищенные 422 без эха входных значений и генерирует OpenAPI 3.1 для Swagger UI (`/docs`, `/openapi.json`). Переход на FastAPI — механическая замена декораторов. |
| SQLAlchemy | **sqlite3** (stdlib), весь SQL в `backend/app/database/db.py` | Только параметризованные запросы. Для PostgreSQL достаточно переписать один файл. |
| XGBoost / LightGBM | **scikit-learn HistGradientBoostingClassifier** | Тот же класс алгоритмов (гистограммный градиентный бустинг), нативно обрабатывает пропуски (NaN). |
| SHAP | **Групповая окклюзия** (`backend/app/services/explain.py`) | Группа признаков заменяется на типичное легитимное значение, и измеряется изменение log-odds. Это **не SHAP**, так и подписано везде. Верность объяснений проверяется deletion-тестом. |
| pytest + TestClient | **unittest** + собственный ASGI-клиент (`backend/tests/asgi_client.py`) | Тесты совместимы с pytest, если он установлен. |
| Vite | **esbuild** (`frontend/build.mjs`) | Vite сам использует esbuild. Сборка в `frontend/dist`, которую раздаёт backend. Так дашборд и API работают на одном origin: один процесс, один порт, без CORS. |
| Tailwind CSS | **Свой CSS с токенами** (`frontend/src/styles.css`) | Тёмная fintech-тема; цвета заданы переменными на `:root`. |
| Recharts | **Свои SVG-графики** (`frontend/src/components/charts.tsx`) + **d3-force** для графа | Каждый график с наведением и легендой. Категориальная палитра проверена валидатором на различимость при дальтонизме (CVD ΔE ≥ 8). |
| React Router | **Hash-роутер** (~20 строк в `main.tsx`) | Работает без серверных маршрутов. |
| @types/react | **Минимальный shim** (`frontend/src/react-shim.d.ts`) | `tsc --noEmit` проходит, пропсы компонентов проверяются. Если поставить @types/react локально, shim нужно удалить. |
| GNN | **Графовые алгоритмы NetworkX** | Фан-ин окна, быстрые цепочки пересылки, общие получатели. GNN нельзя честно обучить на синтетике такого размера, и нейросеть здесь не имитируется. |
| Локальный LLM | **Шаблонный генератор отчётов** | Подписан как «template-based, no LLM». |
| Публичный датасет | **Синтетический генератор** с seed | Внешние датасеты скачать было нельзя. Скрипт для публичного датасета — задача части 3 (см. HANDOFF). |

## Ключевые методологические решения

- **Разбиение по времени**: дни 0–6 — burn-in (базовые профили ещё формируются), 7–59 — train, 60–74 — validation, 75–89 — test. Выбор модели и все пороги — только по validation.
- **Без утечек**: все контекстные признаки считаются из состояния *до* транзакции. Жалобы о мошенничестве приходят с задержкой 6–120 ч.
- **Область**: переводы и оплата счетов. Карточные платежи генерируются только для истории клиента: CNP-фрод — отдельная задача.
- **Сравнение с правилами**: (a) точка ROC при ровно том же test recall, что у правил; (b) развёртываемый протокол с порогом из validation. Отдельно показан FPR при фиксированных recall.
- **Политика**: MEDIUM — порог, дающий 95% recall на validation, но не более 4% алертов. HIGH — минимальный порог с precision ≥ 90% на validation. Строгий режим: 98% / 6% / 75%.
- **Защитные правила**: одно лишь поведенческое отклонение не может привести к рекомендации удержания (понижение HIGH→MEDIUM). Отсутствующие данные никогда не атрибутируются как фактор риска. Один сигнал соцынженерии ограничен 45 баллами.
- **Найденный и исправленный баг** (для честности): в первой версии генератора окно `transactions_last_24h` по ошибке было 24 дня. Ошибку нашли по странным объяснениям («скорость транзакций» как фактор). После исправления данные и модели пересчитаны. Все опубликованные результаты — после исправления.

## Часть 4: исправления v2 и стресс-тесты

**Найдено при разборе сегмента «переводы на счета младше 30 дней»** — две ошибки измерения. Обе исправлены, все результаты пересчитаны. Результаты v1 сохранены в `experiments/results/v1_before_flowfix/`.

1. **Навигация сравнивалась с несопоставимой нормой.** Добавление нового получателя — другой экранный сценарий, а норма клиента строилась в основном по переводам знакомым. Теперь путь по экрану сравнивается только с нормой того же сценария (`bl_screen_flow`, не меньше 3 сессий). Иначе метрика помечается как «несопоставимая» и не используется. В API это поля `behavioral.screen_flow` и `screen_flow_sessions`; несовпадение сценария даёт 422.
2. **«Пересылкой» считались траты в магазинах.** Теперь pass-through = только переводы на другие счета ÷ входящие деньги. Сигнал засчитывается лишь в диапазоне 60–130%: отправить намного больше полученного — значит тратить свои деньги.

Эффект на тесте: PR-AUC 0,862 → 0,879; ложные тревоги на счетах < 30 дней 10,2% → 9,0% (у правил 2,1%).

**Модель без признака «возраст получателя»** отклонена правилом, заданным до просмотра теста: validation PR-AUC 0,927 против 0,956.

**Отдельный порог для счетов < 30 дней** выбран на validation (минимум ложных тревог при потере ≤ 2 п.п. recall). На тесте: ложные тревоги 9,0% → 1,6%, но recall по мошенничеству на такие счета 95,8% → 89,6%. Это решение политики, поэтому порог доступен как опция в настройках, выключенная по умолчанию.

**Стресс-тест «хитрый мошенник»** (`ml/evaluation/adversary.py`) — проверка «что если» на синтетике. **Нагрузочный тест** (`scripts/load_test.py`): у uvicorn с двумя процессами в этой среде есть транспортная задержка ~44 мс даже на `/health`; к модели она не относится.

## Публичные датасеты: оценка пригодности

Скачать датасеты из среды разработки не удалось: OpenML и raw.githubusercontent заблокированы политикой сети. Оценка по описаниям:

| Датасет | Что даёт | Чего нет для NeuroShield | Вывод |
|---|---|---|---|
| Credit Card Fraud (ULB, Kaggle) | реальные метки, 284 807 карточных операций, время | признаки скрыты PCA (V1–V28); нет получателя, поведения и графа; это CNP-карты, а не переводы | годится только для проверки транзакционной модели и калибровки на реальном дисбалансе (0,17%) |
| PaySim (Kaggle) | мобильные переводы с отправителем и получателем — можно построить граф | сам синтетический (симулятор на основе реальных логов); нет поведения и социальной инженерии | хорош для графового компонента и мулов; новых доказательств «реальности» не даёт |
| IEEE-CIS Fraud (Kaggle) | реальные e-commerce операции, устройства | не переводы между счетами, нет графа получателей | частично: признаки устройства |

Ни один открытый датасет не содержит меток социальной инженерии и согласованной поведенческой телеметрии. Поэтому главный путь проверки — этап 1 дорожной карты на данных банка. Самый дешёвый следующий шаг — прогнать транзакционную часть на ULB для проверки дисбаланса и калибровки.

## Часть 5: сервер, устойчивость, публичные данные, GitHub

- **Задержка 44 мс у двух процессов — найдена и устранена.** uvicorn в режиме `--workers N` создаёт слушающий сокет как `socket.socket(family=...)` с `proto = 0`. asyncio включает TCP_NODELAY только при `proto == IPPROTO_TCP`, поэтому ответ (заголовки и тело отдельными записями) ждал отложенного ACK клиента. Исправление — `backend/app/main.py`: TCP_NODELAY на всех принятых TCP-соединениях. Тест — `backend/tests/test_server.py`. После исправления: два процесса при одном клиенте p50 56 → 11 мс, пропускная способность ~165 запросов/с.
- **Обучение на примерах обхода — не принято.** `ml/evaluation/robust_training.py`: приёмы обхода поделены на «знакомые» (используются при обучении) и «незнакомые» (только для проверки), правило принятия задано заранее по validation. Против знакомых приёмов recall на тесте 78,0% → 81,0%, против незнакомых 80,2% → 77,9%; модель отклонена. Вывод: подгонка под известные трюки не даёт устойчивости к новым.
- **Публичный датасет ULB.** Скачать по-прежнему не удалось (сеть). Готов скрипт `python -m ml.evaluation.public_ulb creditcard.csv`: тот же протокол (разбиение по времени, LR и бустинг, CI, калибровка) на реальных метках. Скрипт проверен на макете с той же схемой (тест в `test_features.py`).
- **GitHub.** Проект оформлен как git-репозиторий; CI (`.github/workflows/ci.yml`) проверяет тесты, сборку фронтенда, Docker-образ и UI в контейнере при каждом push.
